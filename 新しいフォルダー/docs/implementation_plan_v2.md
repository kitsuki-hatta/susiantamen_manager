# 追加変更仕様書 v2（最終確定版）

## 概要

本書は、初回統合実装（README.md / implementation.md / task.md）に基づき構築された
「漁場生産力・水産多面的機能強化対策 活動管理システム（大分県・藻場/干潟版）」に対する
2次改修の変更仕様を定義する。

- 前提: 既存実装（moba_ プレフィックス、藻場/干潟版データモデル）を維持したまま改修
- 分離要件: アサリ版（asari_）との分離ルールは従来どおり厳守
- 各項目は原則独立着手可能。優先度と依存は「14. 実装順序」を参照

## 1. モーダルの閉じ操作の変更

### 背景
モーダル外クリックで閉じる挙動により、入力中に意図せず閉じてデータが失われる事故が多発。

### 変更内容
- オーバーレイ（背景）クリックでは閉じない。
- モーダルは「キャンセル」「保存」「×」ボタン操作でのみ閉じる。
- 保存成功時のみ閉じる。バリデーションエラー時は閉じずエラー表示。
- Escキーは「キャンセル」と同等（任意採用）。

### 対象
- 共通モーダル制御（ui/navigation 系）

### 受け入れ基準
- [ ] オーバーレイクリックで閉じない
- [ ] ボタン操作でのみ閉じる
- [ ] エラー時は閉じずエラー表示

## 3. 作業計画・実績・支払・物品消費の紐付け強化【重要・細分化】

### 背景
計画・実績・支払・物品が個別入力で紐付けが弱い。「計画→実績→支払」を連結し二重入力を解消。

### 全体方針
- 紐付け基点は作業計画（moba_plan）。「計画 → 実績 → 支払」の親子関係。
- 計画外（突発）実績にも対応（planId=null を許容）。
- 支払は既存 moba_budget_expense を使用（recordIds[] で多対多）。
- 物品消費は invLog(type="out") と在庫に連動。

### データ構造
- moba_record.planId: number | null（null=計画外）
- moba_record.usedItems[]: { itemId, name, qty, unit }
- moba_budget_expense.recordIds[]: number[]

### 3-1. 実績の計画紐付け（親子関係）
- 実績入力時に「対象の作業計画を選択」または「計画外」を選択可能。
- 計画選択時、日付・地区・活動項目・予定人員等を初期値として引き継ぐ。
- 受け入れ基準:
  - [ ] 計画選択で planId が入り初期値が引き継がれる
  - [ ] 「計画外」で planId=null の実績を作成できる

### 3-2. 実績の作業内容入力（1画面集約）
- 作業時間（start/end、時給時は自動算出）、参加者・用船者・車両提供者、潜水有無、特記事項を1画面入力。
- 受け入れ基準:
  - [ ] 1画面で作業内容一式を入力・保存できる
  - [ ] 時給方式で作業時間が自動算出される

### 3-3. 物品消費の連動
- 実績の使用物品（消耗品の消費数量）入力で invLog(out) を生成/更新し在庫減算。
- 実績の編集・削除時に invLog も整合更新。
- 受け入れ基準:
  - [ ] 実績の使用物品が invLog(out)・在庫に反映される
  - [ ] 実績の修正/削除で在庫が整合する

### 3-4. 支払実績の紐付け
- 実績画面から該当作業への支払実績（moba_budget_expense）を紐付け・確認・解除できる。
- 1支払を複数実績に、1実績を複数支払に紐付け可能（多対多）。
- 受け入れ基準:
  - [ ] 実績に支払を紐付け・解除できる
  - [ ] 多対多の紐付けが保存・表示される

### 3-5. 充足状況の可視化
- ダッシュボード/支払集計で「計画あり・実績あり・支払あり」の充足状況と未入力を表示。
- 支払未入力判定＝実績算出額?既支払額（複数紐付けは算出額比率按分、比率0は均等割り）。
- 受け入れ基準:
  - [ ] 計画/実績/支払の充足・未入力が一覧で分かる
  - [ ] 未払い額が正しく算出される

### 対象（No.3全体）
- plan.js / record.js / inventory.js / budget.js / dashboard.js / payment.js / calc.js

### 変更内容

### データ構造

### 対象

### 受け入れ基準

## 10. 様式5 位置図：地理院地図＋協定範囲ポリゴン＋作図＋Excel画像埋込

### 背景
位置図を実用化し、地図上で協定範囲・作業位置・コメントを示し、報告書に画像添付したい。

### ★ライセンス確認【実装前提条件・必須】
- 地理院タイルを事前取得して同梱・オフライン利用し、作成した位置図を県・国へ提出する運用は、
  「機関内部利用」の範囲を超える可能性があり、測量法上の複製・使用承認が必要となる場合がある。
- したがって本機能は、以下を「運用開始の前提条件」とする:
  1. 出典明示（「出典：国土地理院（地理院タイル）」）を画面・Excel出力の双方に必ず実装・表示。
  2. 運用開始前に、大分県（事業所管部局）を通じて国土地理院へ利用可否を照会し、
     必要であれば承認申請（無償・オンライン申請可）を行うこと。
  3. 「既存組織で使用実績がある」ことは適法性の根拠にしない。
- 照会結果に依存しないよう、実装は「同梱方式」と「オンライン参照方式」を切替可能に設計する。

### 変更内容
- 位置図エディタに国土地理院タイルを背景表示。
  - 方式1（主軸・同梱）: 活動範囲に限定したタイルを組織ごとのフォルダに配置しローカル参照。
    - 例: assets/gsi_tiles/{org_id}/{z}/{x}/{y}.png
    - 対象は選択市町村役場を原点とした活動範囲、ズーム Z14?18 に限定。
  - 方式2（フォールバック・オンライン）: タイルを都度オンライン参照（一時キャッシュのみ）。
  - moba_settings.mapTileMode: "bundled" | "online" で切替。
- 単価・設定タブに市町村入力欄を新設し、選択市町村の役場座標を地図初期原点とする（初期 Z16 目安）。
- 地図上に作業位置マーカー＋コメントを配置。
- 協定範囲（活動範囲）ポリゴンを地図に重ね描画（詳細は No.12）。
- 既存の作図（矩形・円・テキスト・アップロード背景画像）も併存。
- 完成した位置図を Excel 出力時に画像（PNG）として埋め込む。出典表記も画像内または近傍に明記。

### データ構造
- moba_settings.mapTileMode: "bundled" | "online"
- moba_settings.municipality: { code, name, lat, lng }（No.11）
- moba_form5[recordId].map:
  - baseType: "gsi_tile" | "uploaded_image" | "none"
  - center: {lat,lng}, zoom: number
  - shapes[]: { type:"rect"|"circle"|"text"|"marker", coords, color, text }

### 対象
- master.js（市町村入力・タイルモード）/ form5-map.js（地図・ポリゴン・作図統合）/ form5.js（画像埋込）
- 同梱: assets/gsi_tiles/{org_id}/

### 受け入れ基準
- [ ] 選択市町村役場を原点に地図が表示される（Z14?18可変）
- [ ] 同梱/オンラインのタイルモードを切替できる
- [ ] 地図上にマーカー＋コメントを配置できる
- [ ] 既存の矩形/円/テキスト作図も併用できる
- [ ] Excel出力に位置図が画像として埋め込まれる
- [ ] 地理院タイルの出典が画面・出力に必ず明記される

## 12. 協定範囲（活動範囲）ポリゴンの保持と重ね合わせ【新規】

### 背景
各活動組織の協定範囲（活動範囲）を地図に重ねて示したい。

### 変更内容
- 協定範囲を GeoJSON（Polygon / MultiPolygon）として取込・保存する。
  - ブラウザ完結型のため、標準は GeoJSON を採用。
  - Shapefile 等を持つ場合は、事前に GeoJSON へ変換して取り込む運用（QGIS等）。手順は別途整備。
- 単価・設定タブで協定範囲 GeoJSON を取込・確認・削除できる。
- 様式5位置図で、地図タイルの上に協定範囲ポリゴンを半透明で重ね描画。
  - 枠線色・塗り色・不透明度を設定可能。
- 作業位置マーカー・協定範囲・地図タイルを同時表示し、Excelへ画像埋込。

### データ構造
- moba_settings.activityArea:
  - geojson: GeoJSON(FeatureCollection|Polygon|MultiPolygon)
  - style: { strokeColor, fillColor, opacity }
- （組織ごとに複数範囲を持つ場合は activityAreas[] 配列化も可）

### 対象
- master.js（GeoJSON取込UI）/ form5-map.js（ポリゴン重ね描画）/ form5.js（画像埋込に反映）

### 受け入れ基準
- [ ] 協定範囲GeoJSONを取込・保存・削除できる
- [ ] 位置図上に協定範囲が半透明で重なって表示される
- [ ] 枠線色・塗り色・不透明度を設定できる
- [ ] Excel出力画像に協定範囲が反映される

## 13. 分離要件（再掲・厳守）

- 全 localStorage キーは moba_ プレフィックスを維持。
- 追加項目（planByPeriod、色/パターン、municipality、mapTileMode、activityArea、
  潮位メモ、map.shapes 等）も moba_ 配下。
- バックアップ format = moba_full_backup_v1 を維持し、追加データも内包。
- アサリ版（asari_）とのデータ混在を発生させない。
- 同梱タイル（assets/gsi_tiles/）はlocalStorage対象外（静的ファイル）だが、
  バックアップ対象外である旨をドキュメントに明記。
