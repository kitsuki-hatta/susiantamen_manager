# 追加変更仕様書 v4（完成版）

## 概要

本書は、implementation_v3.md に基づく実装後に判明した改善・機能追加・様式1整備を定義する
4次改修仕様である。

- 前提: v1（統合）+ v2 + v3 実装済み。moba_ プレフィックス、藻場/干潟版データモデルを維持
- 分離要件: アサリ版（asari_）との分離ルールは従来どおり厳守
- No.6（様式1）は計算式・変数定義・端数処理・申請回判定・入出力対応・エッジケースまで厳密化
- 交付申請額は上限クリップ（採択額を超えない）を確定仕様とする

## 1. デバッグ用データと全データ削除ボタン

### 背景
動作確認用のサンプルデータが欲しい。本運用時に一括削除できる導線も必要。

### 変更内容
- 初回起動時、moba_ データが空の場合にデバッグ用サンプルデータを投入する。
  - 組織基本設定・地区/メンバー・活動項目・単価・作業計画/実績・物品/入出庫・
    予算/支払・潮汐（少量）など、全機能を確認できる最小限の一式。
  - デバッグデータには識別フラグ（例: _debug:true）または投入元マークを持たせる。
- 単価・設定タブに「全データ削除」ボタンを設置。
  - 押下で確認ダイアログ → 全 moba_ データを初期化（アサリ版 asari_ には触れない）。
  - 削除後は空状態（本運用開始状態）にする。

### データ構造
- 各データに debugSeed?: boolean（任意）／または moba_meta.seeded: boolean

### 対象
- storage.js（シード投入・初期化）/ master.js（削除ボタンUI）

### 受け入れ基準
- [ ] 空状態の初回起動でサンプルデータが入る
- [ ] 単価・設定タブの「全データ削除」で全moba_データが初期化される
- [ ] 削除確認ダイアログが出る
- [ ] アサリ版データに影響しない

## 6. 報告書 様式1 の整備【厳密版・確定】

### 背景
様式1（交付申請書）の金額・申請回・端数処理・口座・レイアウトを自動化/厳密化し、
手入力を原則なくす。交付金は事業開始からの累計精算方式とする。

### 全体方針
- 様式1の各項目は、予算管理・交付金収受フロー・様式2・作業計画/実績・組織基本設定から
  自動算出/参照する。
- ユーザー入力は原則、6-3 の「申請対象の締め日」と「見込みを含むか／見込みの対象期日」のみ。
- 金額は税込・円単位で内部計算し、最終申請額のみ千円未満切り捨て。
- 交付申請額は採択予算額を超えないよう上限クリップする（確定・解除不可）。

---

### 用語・変数定義（No.6共通）

- approvedAmount：採択予算額（moba_budget.approvedAmount）
- grantReceived：既交付額。交付金収受フロー type="council_to_org" の入金合計
  （moba_grant_flow.entries[].amount の合計）
- cutoffDate：申請対象の締め日（ユーザー指定、6-3）
- paidCumulative：事業開始?cutoffDate に「支払日(paidDate) ? cutoffDate」で実際に支払った
  支払実績の累計（moba_budget_expense の amount 合計）
- includeForecast：見込みを含めるか（ユーザー選択、真偽）
- forecastCutoffDate：見込みの対象期日（ユーザー指定、includeForecast=true 時のみ。
  forecastCutoffDate ? cutoffDate を必須）
- forecastAmount：見込み額。includeForecast=true のとき、
  cutoffDate 超?forecastCutoffDate に発生予定の
  (a) 様式2の執行見込み（未払い分の予定額）＋
  (b) 未実施の作業計画に基づく発生予定額（作業計画×単価、calc.js見積ロジック流用）
  の合計。支払済み（paidCumulative計上分）と二重計上しない。
- remainingGrant：申請可能な残り枠 = approvedAmount ? grantReceived
- roundDown1000(x)：x の千円未満を切り捨てる関数（floor(x/1000)*1000、x<0 は 0）

---

### 6-1. 既交付額の自動集計
- 定義: grantReceived = Σ(moba_grant_flow.entries[type="council_to_org"].amount)
  （申請時点までに実際に入金された全額。未入金は原則発生しない。
   前回申請済みなのに入金0なら入力忘れの可能性がある旨を警告表示する）
- 対象: form1.js / budget.js
- 受け入れ基準:
  - [ ] 既交付額が「協議会→組織」入金合計と一致する
  - [ ] 手入力できない
  - [ ] 前回申請済みなのに入金0の場合は入力忘れ警告を出す

### 6-2. 申請回（第何回）の自動判定
- 定義: applicationRound =（「協議会→組織」入金件数）+ 1
  （0件→第1回、1件→第2回、2件→第3回）
- 対象: form1.js
- 受け入れ基準:
  - [ ] 入金件数 + 1 で申請回が自動判定される

### 6-3. 交付申請金額の自動計算【中核ロジック・厳密化・上限クリップ確定】

#### ユーザー入力（この項目のみ手入力を許容）
- cutoffDate：申請対象の締め日（日付指定）
- includeForecast：見込みを含めるか（チェック）
- forecastCutoffDate：見込み対象期日（includeForecast=true のとき日付指定。
  forecastCutoffDate ? cutoffDate を必須）

#### 期別の目安期間（運用参考・自動入力はしない）
- 第1回=4月?7月中旬 / 第2回=7月中旬?11月頃 / 第3回=11月頃?2月

#### 基準額（支払実績・累計方式）
- paidCumulative = Σ amount（moba_budget_expense のうち paidDate ? cutoffDate）
  ※事業開始からの累計。期間内合計ではない。

#### 見込み額（未来の作業も含む）
- includeForecast=false のとき forecastAmount = 0
- includeForecast=true のとき:
  forecastAmount =
    (様式2の執行見込みのうち cutoffDate 超?forecastCutoffDate に支払予定の未払い分)
    + (未実施の作業計画に基づく cutoffDate 超?forecastCutoffDate の発生予定額)
  ※支払済み分は二重計上しない

#### 申請額の算出（最後に1回だけ千円未満切り捨て）
- remainingGrant = approvedAmount ? grantReceived
- baseBeforeRound = (paidCumulative + forecastAmount) ? grantReceived
- clipped = min(baseBeforeRound, remainingGrant)   // 上限クリップ（確定）
- applicationAmount = (clipped ? 0) ? 0 : roundDown1000(clipped)
  ※端数処理は最終額に1回だけ適用
  ※applicationAmount は 0 以上、かつ remainingGrant を超えない
  ※上限クリップはユーザー解除不可

#### 上限クリップ発生時の挙動
- clipped = remainingGrant（上限到達）の場合:
  - 申請額を残枠に丸め、画面とWord出力前に
    「採択額の上限に達したため申請額を上限に調整しました」と警告。
  - 内訳表示に「上限クリップ適用」フラグを明示。
- remainingGrant ? 0（既に採択額まで交付済み）の場合:
  - 申請額 = 0 とし「申請可能な残枠がありません」と警告。

#### 表示・検証
- 画面に内訳（paidCumulative / forecastAmount / grantReceived / remainingGrant /
  切り捨て前 / 申請額 / 上限クリップ有無）を表示し根拠を確認できる。
- applicationAmount=0 の場合、および上限クリップ発生時は警告表示。

- データ: moba_budget_expense（支払・paidDate）/ 様式2執行見込み /
  moba_plan（未実施作業）/ 単価マスタ / grantReceived(6-1) / approvedAmount
- 対象: form1.js / calc.js / budget.js
- 受け入れ基準:
  - [ ] 申請額 = roundDown1000( min((paidCumulative+forecastAmount)?grantReceived,
        approvedAmount?grantReceived) )（0以下は0）で算出される
  - [ ] cutoffDate までの支払累計が基準になる（累計方式）
  - [ ] includeForecast=true で見込み（未払い＋未実施作業、forecastCutoffDateまで）が加算される
  - [ ] forecastCutoffDate ? cutoffDate を検証する
  - [ ] 千円未満切り捨てが最終額に1回だけ適用される
  - [ ] 累計申請額が採択予算額を超えないよう上限クリップされる
  - [ ] 上限クリップ発生時に警告表示され内訳にフラグが出る
  - [ ] 残枠0以下・計算0以下は申請額0＋警告
  - [ ] 上限クリップはユーザー解除不可
  - [ ] 内訳が画面で確認できる

### 6-8. エッジケース・検証仕様
- 支払実績の paidDate 未設定レコードは集計対象外とし、件数を警告表示。
- cutoffDate より未来日の支払実績は paidCumulative に含めない。
- includeForecast=true かつ forecastCutoffDate < cutoffDate は入力エラー。
- 見込みと支払実績の二重計上防止（同一計画に紐づく支払済み分は見込みから除外）。
- approvedAmount 未設定/0 はエラー（申請額計算不可）として明示。
- grantReceived > approvedAmount（過交付）は異常警告＋申請額0。
- 千円未満切り捨て後も remainingGrant を超えないことを検証。
- 申請額0・上限クリップ発生時は Word出力前に確認ダイアログで通知。
- 対象: form1.js / calc.js / budget.js
- 受け入れ基準:
  - [ ] paidDate未設定・未来日支払が正しく除外/警告される
  - [ ] forecastCutoffDate < cutoffDate がエラーになる
  - [ ] 見込みと支払実績が二重計上されない
  - [ ] 採択額未設定/0・過交付・申請額0・上限クリップが警告される
