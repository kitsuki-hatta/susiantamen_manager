## 3. 作業計画・実績・支払・物品消費の紐付け強化【詳細分割】

### 背景
計画・実績・支払・物品が個別入力で紐付けが弱い。「計画→実績→支払」を連結し二重入力を解消。

### 全体方針
- 紐付け基点は作業計画（moba_plan）。「計画 → 実績 → 支払」の親子関係。
- 計画外（突発）実績にも対応（planId=null を許容）。
- 支払は既存 moba_budget_expense を使用（recordIds[] で多対多）。
- 物品消費は invLog(type="out") と在庫に連動。

### 共通データ構造
- moba_record.planId: number | null（null=計画外）
- moba_record.usedItems[]: { itemId, name, qty, unit }
- moba_budget_expense.recordIds[]: number[]

---

### 3-1. データモデル整備（前提タスク）
- 内容:
  - moba_record に planId / usedItems[] / tideLevel? / tideNote? のスキーマを追加。
  - 既存レコードに対する後方互換（未設定時は planId=null, usedItems=[] とみなす）。
  - storage.js のデフォルト値・マイグレーション処理を追加。
- 対象: storage.js / record.js
- 受け入れ基準:
  - [ ] 既存データを開いてもエラーにならない（後方互換）
  - [ ] 新規実績に planId / usedItems が保存される

### 3-2. 計画→実績の生成導線
- 内容:
  - 作業計画一覧/カレンダーの各計画から「実績を作成」導線を追加。
  - 計画選択で日付・地区・活動項目・予定人員を初期値として引き継ぐ。
- 対象: plan.js / record.js
- 受け入れ基準:
  - [ ] 計画から実績作成でき planId が設定される
  - [ ] 初期値が計画から引き継がれる

### 3-3. 計画外（突発）実績の作成
- 内容:
  - 実績タブから「計画外実績」を直接新規作成（planId=null）。
  - 計画外である旨を一覧・詳細に表示（バッジ等）。
- 対象: record.js
- 受け入れ基準:
  - [ ] planId=null の実績を作成・保存できる
  - [ ] 計画外であることが視覚的に分かる

### 3-4. 実績入力画面の1画面集約
- 内容:
  - 作業時間（start/end、時給時は自動算出）、参加者・用船者・車両提供者、
    潜水有無、天候、特記事項を1画面に集約。
  - 必須チェック（activityCode / diving / note）を維持。
- 対象: record.js / calc.js（作業時間算出）
- 受け入れ基準:
  - [ ] 1画面で作業内容一式を入力・保存できる
  - [ ] 時給方式で作業時間が自動算出される
  - [ ] 必須項目未入力時に保存できずエラー表示

### 3-5. 物品消費（消耗品）の実績連動
- 内容:
  - 実績で使用物品と消費数量を入力すると invLog(type="out") を生成し在庫を減算。
  - 消耗品/備品の区別に応じた挙動（消耗品は減算、備品は使用記録のみ 等）。
- 対象: record.js / inventory.js
- 受け入れ基準:
  - [ ] 使用物品入力で invLog(out) が生成され在庫が減る
  - [ ] 消耗品と備品で挙動が正しく分かれる

### 3-6. 物品消費の編集・削除整合
- 内容:
  - 実績の使用物品を編集/削除した際、対応する invLog(out) と在庫を整合更新。
  - 実績自体の削除時も関連 invLog を取り消し在庫を戻す。
- 対象: record.js / inventory.js
- 受け入れ基準:
  - [ ] 使用物品の増減修正が在庫に正しく反映される
  - [ ] 実績削除で在庫が元に戻る

### 3-7. 支払実績の紐付け（多対多）
- 内容:
  - 実績画面から支払実績（moba_budget_expense）を紐付け・解除。
  - 1支払を複数実績に、1実績を複数支払に紐付け可能。
  - 予算管理側からの紐付け（recordIds編集）とも双方向で整合。
- 対象: record.js / budget.js
- 受け入れ基準:
  - [ ] 実績から支払を紐付け・解除できる
  - [ ] 予算管理側の変更と双方向で整合する

### 3-8. 充足状況・未払い算出の可視化
- 内容:
  - ダッシュボード/支払集計で「計画あり・実績あり・支払あり」の充足状況と未入力を表示。
  - 未払い額＝実績算出額?既支払額。複数紐付けは算出額比率で按分（比率0は均等割り）。
- 対象: dashboard.js / payment.js / calc.js
- 受け入れ基準:
  - [ ] 計画/実績/支払の充足・未入力が一覧で分かる
  - [ ] 未払い額が正しく算出される（按分含む）

### 対象（No.3全体）
- storage.js / plan.js / record.js / inventory.js / budget.js / dashboard.js / payment.js / calc.js

## 10. 様式5 位置図：地理院地図＋作図＋Excel画像埋込【詳細分割】

### 背景
位置図を実用化し、地図上で協定範囲・作業位置・コメントを示し、報告書に画像添付したい。

### ★ライセンス確認【実装前提条件・必須】
- 地理院タイルを事前取得して同梱・オフライン利用し、作成した位置図を県・国へ提出する運用は、
  「機関内部利用」の範囲を超える可能性があり、測量法上の複製・使用承認が必要となる場合がある。
- 本機能は以下を「運用開始（配布）の前提条件」とする:
  1. 出典明示（「出典：国土地理院（地理院タイル）」）を画面・Excel出力の双方に必ず実装・表示。
  2. 運用開始前に、大分県（事業所管部局）を通じて国土地理院へ利用可否を照会し、
     必要であれば承認申請（無償・オンライン申請可）を行う。
  3. 「既存組織で使用実績がある」ことは適法性の根拠にしない。
- 照会結果に依存しないよう、同梱方式とオンライン参照方式を切替可能に設計する。

### 共通データ構造
- moba_settings.mapTileMode: "bundled" | "online"
- moba_settings.municipality: { code, name, lat, lng }（No.11）
- moba_form5[recordId].map:
  - baseType: "gsi_tile" | "uploaded_image" | "none"
  - center: {lat,lng}, zoom: number
  - shapes[]: { type:"rect"|"circle"|"text"|"marker", coords, color, text }

---

### 10-1. 地図ビューア基盤の導入
- 内容:
  - 位置図エディタにスリムな地図ビューア（軽量ライブラリ or 自前タイル描画）を導入。
  - タイルURLテンプレートを切替可能（bundled=ローカルパス / online=地理院URL）。
  - オフライン前提のため外部CDN依存を避け、ライブラリはローカル同梱。
- 対象: form5-map.js / index.html（lib同梱）
- 受け入れ基準:
  - [ ] 地図ビューアが表示され、pan/zoom（Z14?18）できる
  - [ ] 外部CDNに依存せず動作する

### 10-2. タイルモード切替（同梱/オンライン）
- 内容:
  - moba_settings.mapTileMode により、ローカル同梱タイルとオンライン参照を切替。
  - 同梱: assets/gsi_tiles/{org_id}/{z}/{x}/{y}.png を参照。
  - オンライン: 地理院タイルを都度参照（一時キャッシュのみ、恒久保存しない）。
  - タイル欠損時のプレースホルダ表示。
- 対象: master.js（モード設定UI）/ form5-map.js
- 受け入れ基準:
  - [ ] 同梱/オンラインを設定で切替できる
  - [ ] 同梱タイルが無い範囲でプレースホルダ表示になる

### 10-3. 初期原点（市町村役場）連携
- 内容:
  - No.11 の市町村役場座標を地図の初期中心に設定（初期 Z16 目安）。
  - 位置図ごとに center/zoom を moba_form5[recordId].map に保存し次回復元。
- 対象: form5-map.js / master.js
- 受け入れ基準:
  - [ ] 選択市町村役場を初期中心に地図表示される
  - [ ] 位置図ごとの center/zoom が保存・復元される

### 10-4. 作業位置マーカー＋コメント
- 内容:
  - 地図クリックでマーカー追加、コメント（テキスト）を付与・編集・削除。
  - shapes[] に type:"marker" として保存（coords=緯度経度, text=コメント）。
- 対象: form5-map.js
- 受け入れ基準:
  - [ ] マーカーを追加・移動・削除できる
  - [ ] マーカーにコメントを付与・編集できる

### 10-5. 既存作図（矩形・円・テキスト）の併存
- 内容:
  - 既存の矩形・円・テキスト・アップロード背景画像の作図機能を地図レイヤ上でも使えるよう統合。
  - 地図座標系と描画レイヤの整合（地図移動時に図形が追従）。
- 対象: form5-map.js
- 受け入れ基準:
  - [ ] 矩形/円/テキストを地図上に描画できる
  - [ ] 地図をpan/zoomしても図形が正しい位置に追従する

### 10-6. Excel画像埋込
- 内容:
  - 地図＋協定範囲＋図形＋マーカーを合成し canvas→PNG(base64) を生成。
  - ExcelJS の addImage で様式5シートへ埋込。出典表記も画像内 or 近傍に明記。
- 対象: form5.js / form5-map.js
- 受け入れ基準:
  - [ ] 位置図がPNGとしてExcelに埋め込まれる
  - [ ] 出典「国土地理院（地理院タイル）」が出力に明記される

### 10-7. 同梱タイル準備手順の整備（開発運用）
- 内容:
  - 組織ごとの活動範囲・Z14?18に限定したタイル取得・配置の手順書を作成。
  - assets/gsi_tiles/{org_id}/ の構成規約を明文化。
  - ※本手順の実行（実タイル取得）はライセンス確認完了後に行う。
- 対象: docs（手順書）/ assets/gsi_tiles/
- 受け入れ基準:
  - [ ] タイル配置規約と取得手順がドキュメント化される
  - [ ] サンプル1組織分で同梱表示が確認できる

## 12. 協定範囲（活動範囲）ポリゴンの保持と重ね合わせ【詳細分割】

### 背景
各活動組織の協定範囲（活動範囲）を地図に重ねて示したい。

### 共通データ構造
- moba_settings.activityArea:
  - geojson: GeoJSON(FeatureCollection|Polygon|MultiPolygon)
  - style: { strokeColor, fillColor, opacity }
- （複数範囲を持つ場合は activityAreas[] に拡張可）

---

### 12-1. GeoJSON取込・保存
- 内容:
  - 単価・設定タブで協定範囲 GeoJSON ファイルを取込・保存・削除。
  - 取込時に Polygon/MultiPolygon の妥当性を簡易検証（座標系はWGS84想定）。
  - Shapefile は事前に GeoJSON へ変換する運用（変換手順を docs に記載）。
- 対象: master.js / storage.js
- 受け入れ基準:
  - [ ] GeoJSONを取込・保存・削除できる
  - [ ] 不正なGeoJSONを弾きエラー表示する

### 12-2. 位置図への重ね描画
- 内容:
  - 様式5位置図で地図タイル上に協定範囲ポリゴンを半透明で重ね描画。
  - 地図の pan/zoom に追従。
- 対象: form5-map.js
- 受け入れ基準:
  - [ ] 協定範囲が地図上に半透明で重なって表示される
  - [ ] 地図移動/拡大縮小に追従する

### 12-3. スタイル設定
- 内容:
  - 枠線色・塗り色・不透明度を設定・保存（moba_settings.activityArea.style）。
- 対象: master.js / form5-map.js
- 受け入れ基準:
  - [ ] 枠線色・塗り色・不透明度を設定・保存できる
  - [ ] 設定が位置図表示に反映される

### 12-4. Excel出力への反映

  - No.10-6 の合成画像に協定範囲ポリゴンを含めて出力。
- 対象: form5.js / form5-map.js
- 受け入れ基準:
  - [ ] Excel出力画像に協定範囲が反映される

## 13. 分離要件（再掲・厳守）

- 全 localStorage キーは moba_ プレフィックスを維持。
- 追加項目（planByPeriod、色/パターン、municipality、mapTileMode、activityArea、
  潮位メモ、map.shapes、usedItems 等）も moba_ 配下。
- バックアップ format = moba_full_backup_v1 を維持し、追加データも内包。
- アサリ版（asari_）とのデータ混在を発生させない。
- 同梱タイル（assets/gsi_tiles/）・地図ライブラリは静的ファイル（localStorage対象外）。
  バックアップ対象外である旨をドキュメントに明記。
