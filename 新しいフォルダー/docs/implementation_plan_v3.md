# 追加変更仕様書 v3

## 概要

本書は、implementation_v2.md（詳細確定版）に基づく2次改修の実装後に判明した
不具合修正・入力方式の改善・機能追加を定義する3次改修仕様である。

- 前提: v1（統合）+ v2 実装済み。moba_ プレフィックス、藻場/干潟版データモデルを維持
- 分離要件: アサリ版（asari_）との分離ルールは従来どおり厳守
- 本書は「不具合修正（No.3/4/5-2/5-1一部）」と「改善（No.1/2）」「追加（No.6）」を含む
- 不具合項目には想定原因・確認ポイントを付す

---

## 1. 実績入力モーダルの改善

### 1-1. 参加者・用船・車両をメンバー個別選択方式に変更

#### 背景
現在は人数・隻数など「数のみ」の入力。報告書には「誰が作業したか」の情報が必要。

#### 変更内容
- 参加者を、地区に登録されたメンバー名簿から1名ずつ選択（複数選択）する方式に変更。
  - 選択した人数を自動集計し、従来の「人数」手入力欄は廃止（自動算出）。
- 用船・車両も同様に、提供者を名簿から選択し、隻数/台数を自動集計。
- ボランティア等（名簿外の臨時参加者）は、従来どおり人数の数値のみ別途入力（内訳は持たない）。

#### データ構造
- moba_record
  - participants[]: memberId の配列（地区メンバー）
  - vesselProviders[]: memberId の配列（用船提供者）
  - vehicleProviders[]: memberId の配列（車両提供者）
  - volunteerCount: number（名簿外ボランティア人数、数値のみ）
- 集計値（人数＝participants.length + volunteerCount、隻数＝vesselProviders.length 等）は
  保存せず表示時に算出、または派生値として保持（実装都合で可）。

#### 対象
- record.js（入力UI・集計）/ master.js（メンバー名簿参照）/ 各様式（人数等の参照元変更）

#### 受け入れ基準
- [ ] 地区メンバーを複数選択でき、人数が自動集計される
- [ ] 「人数」手入力欄が無くなっている
- [ ] 用船・車両も提供者を選択でき隻数/台数が自動集計される
- [ ] ボランティア人数を数値のみで別途入力できる
- [ ] 報告書に選択メンバー情報／集計値が正しく反映される

### 1-2. 紐付け作業の選択リストを日付昇順に

#### 背景
実績に紐付ける作業計画の選択リストが入力順で並び、探しにくい。

#### 変更内容
- 紐付け対象の作業計画の選択リストを、作業日付の昇順で並べ替えて表示。
- 同一日付内は開始時間の昇順（副次キー）。

#### 対象
- record.js（計画選択リストのソート）

#### 受け入れ基準
- [ ] 作業計画の選択リストが日付昇順で並ぶ
- [ ] 同一日付は開始時間昇順で並ぶ

## 2. 時間入力の15分単位化

### 背景
計画・実績の開始/終了時間は15分単位で十分。

### 変更内容
- 計画・実績の開始/終了時間の入力を15分刻み（00/15/30/45）に統一。
  - セレクト（プルダウン）または step=900 の time入力等で実装。
- 既存の任意分入力データは表示上そのまま許容（新規入力を15分刻みに制限）。

### 対象
- plan.js / record.js（時間入力UI）/ calc.js（作業時間算出は既存ロジック流用）

### 受け入れ基準
- [ ] 計画・実績の時間入力が15分刻みになる
- [ ] 15分刻みで作業時間が正しく算出される

## 3. 物品の入出庫連動の修正【不具合】

### 背景
作業実績から物品（消耗品）を入力すると「入庫」として登録されてしまう。
消費（出庫）として在庫を減算する挙動になっていない。

### 想定原因・確認ポイント
- 実績からの物品消費登録時に invLog の type が "in" になっている可能性（"out" 指定漏れ）。
- 在庫数量の増減方向の符号ミス（out で加算している等）。
- v2 の 3-5/3-6 の実装が未反映、または record→inventory 連動が呼ばれていない可能性。

### 変更内容
- 物品の数量を在庫として管理し、入庫（in）で加算、出庫（out）で減算する。
- 作業実績からの消耗品消費は必ず invLog(type="out") として登録し、在庫を減算する。
- 物品管理タブで入庫・出庫の両方の履歴（invLog）が確認できる。
- 実績の使用物品を編集/削除した場合、対応する out ログと在庫を整合更新（v2 3-6 の再確認）。

### データ構造
- moba_inventory[].qty: number（現在庫）
- moba_invlog[]: { itemId, type:"in"|"out", qty, date, source:"record"|"manual", recordId? }

### 対象
- inventory.js / record.js

### 受け入れ基準
- [ ] 実績からの消耗品消費が out として登録される
- [ ] 出庫で在庫数量が減少する
- [ ] 物品管理で入庫・出庫の両ログが表示される
- [ ] 実績の修正/削除で在庫が整合する

## 4. 作業計画カレンダーの色分けが機能しない【不具合】

### 背景
v2 No.4 で仕様化したカレンダーの色/パターン設定が、設定UIから表示されず機能もしていない。

### 想定原因・確認ポイント
- 単価・設定タブに色/パターン設定UIが実装されていない（未実装）可能性。
- moba_activities[].color / moba_areas[].color 等のスキーマが保存されていない可能性。
- plan.js のカレンダー描画が color/pattern を参照していない可能性。
- calendarColorBasis（activity/area）の切替が未実装の可能性。

### 変更内容（v2 No.4 の再実装・確実な反映）
- 単価・設定タブに、活動項目・地区ごとの表示色・パターン設定UIを表示・保存。
- カレンダー描画で、設定した色/パターンを確実に適用。
- 適用軸（活動項目基準/地区基準）の切替を機能させる（既定は活動項目基準）。

### データ構造（再掲）
- moba_activities[].color, .pattern / moba_areas[].color, .pattern
- moba_settings.calendarColorBasis: "activity" | "area"

### 対象
- master.js（設定UIの表示・保存）/ plan.js（描画反映）

### 受け入れ基準
- [ ] 単価・設定タブに色/パターン設定UIが表示される
- [ ] 設定した色/パターンがカレンダーに反映される
- [ ] 適用軸（活動項目/地区）を切り替えられる

## 5. 報告書出力の修正

### 5-1. 様式1 採択決定額を予算管理の採択予算額と連動

#### 背景
様式1の採択決定額は、予算管理タブの採択予算額と同値であるべき。

#### 変更内容
- 様式1の採択決定額を、予算管理の採択予算額を参照して自動表示（様式1側で手入力しない）。

#### 対象
- form1.js（参照化）/ budget.js（参照元の確認）

#### 受け入れ基準
- [ ] 様式1の採択決定額が予算管理の採択予算額と一致する
- [ ] 様式1側で採択決定額を手入力できない

### 5-2. 様式5 活動記録日誌の入力画面が表示されない【不具合】

#### 背景
報告書出力の様式5サブタブを開くと画面が空で、入力画面が表示されない。

#### 想定原因・確認ポイント
- v2 No.9（サブタブ化）で様式5サブタブの描画関数が未接続の可能性。
- v2 No.10（地図エディタ）導入時の初期化エラーで様式5全体が描画されない可能性
  （地図ライブラリ/タイル参照の例外で描画が止まる等）。
- form5.js / form5-map.js の初期化順・DOM要素未生成の可能性。

#### 変更内容
- 様式5サブタブを開いた際に、活動記録日誌の入力画面が確実に描画されるよう修正。
- 地図初期化に失敗しても、少なくとも入力フォーム（日誌本体）は表示される（地図はフォールバック）。
- コンソールエラーを解消し、サブタブ切替で再描画されるようにする。

#### 対象
- navigation.js（サブタブ→様式5描画の接続）/ form5.js / form5-map.js

#### 受け入れ基準
- [ ] 様式5サブタブで活動記録日誌の入力画面が表示される
- [ ] 地図初期化に失敗しても入力フォームは表示される
- [ ] サブタブ切替で正しく再描画される

## 6. 潮汐データの年単位取込とカレンダー潮位グラフ表示【追加】

### 6-1. 潮汐データの年単位取込

#### 背景
潮汐データは基本的に1年単位（1ファイル＝1年分）で取り込む運用。

#### 変更内容
- 単価・設定タブの潮位取込で、1ファイル＝1年分のデータ取込に対応。
- 取込時に日付ごとに分解し、moba_tide_data の各日キー（YYYY-MM-DD）へ格納。
- 同一日付は上書き。取込結果（対象年・日数・欠損日）を表示。
- 大分港の予測値潮位（1年分）も同様に取込可能。

#### データ構造
- moba_tide_data: { "YYYY-MM-DD": number[24] }（既存踏襲・年分を一括投入）

#### 対象
- master.js（取込UI・年単位パース）/ storage.js

#### 受け入れ基準
- [ ] 1年分ファイルを取込み、日別に分解格納できる
- [ ] 取込結果（対象年・件数・欠損）が表示される
- [ ] 大分港予測値の1年分も取込める

### 6-2. カレンダーの潮位グラフ表示

#### 背景
作業計画カレンダーで、日ごとの潮位変化を素早く確認したい。

#### 変更内容
- 作業計画カレンダー画面の右側に潮位グラフ表示領域を設ける。
- カレンダー上でマウスカーソルが乗っている日の、24時間の潮位変化を折れ線グラフで表示。
- グラフは moba_tide_data[当該日] の number[24] を描画。
- 外部CDN非依存（自前SVG/Canvas、またはローカル同梱ライブラリ）で実装。
- 該当日の潮位データが無い場合は「データなし」を表示。

#### 対象
- plan.js（カレンダーhover連動・グラフ描画）/ 潮位参照ユーティリティ

#### 受け入れ基準
- [ ] カレンダーの日にカーソルを乗せると右側に24時間潮位グラフが出る
- [ ] グラフが該当日の潮位データを正しく描画する
- [ ] データが無い日は「データなし」と表示される
- [ ] 外部CDNに依存せず動作する

## 7. 分離要件（再掲・厳守）

- 全 localStorage キーは moba_ プレフィックスを維持。
- 追加/変更項目（participants/vesselProviders/vehicleProviders/volunteerCount、
  invlog out、color/pattern、tide_data年分 等）も moba_ 配下。
- バックアップ format = moba_full_backup_v1 を維持し、追加データも内包。
- アサリ版（asari_）とのデータ混在を発生させない。
